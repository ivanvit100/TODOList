# Документация API приложения TODOList

## Общая информация
API TODOList предоставляет функциональность для управления списками задач и настройками пользователя. API построено с использованием принципов REST и возвращает данные в формате JSON.

## Аутентификация
API использует JSON Web Token (`JWT`) для аутентификации. Токен хранится в HTTP-only cookie и передается автоматически при каждом запросе.

**Имя cookie**: jwt_token (определяется константой `JWT_COOKIE_NAME`)

**Срок действия токена**: 30 дней (определяется константой `JWT_EXPIRY_DAYS`)

**Алгоритм шифрования**: HS256

### Требования к токену
Многие маршруты API требуют действительного токена аутентификации. Если токен отсутствует, просрочен или недействителен, сервер вернет статус 401 Unauthorized с соответствующим сообщением об ошибке.

## Маршруты API

### Аутентификация и управление учетной записью
#### Валидация токена
**URL**: `/api/v1/validateToken`

**Метод**: Post

**Требуется аутентификация**: Да

**Тело запроса:**
```json
{}
```
**Успешный ответ**:

*Статус*: 200 ОК

**Содержимое**:
```json
{
  "message": "Добро пожаловать",
  "status": "success"
}
```
**Ответы с ошибкой**:
- Статус: `401 Unauthorized`
Если токен истёк или отсутствует
- Статус: `429 Too Many Requests`
При возникновении подозрения на попытку DDoS
- Статус: `500 Internal Server Error`
При возникновении ошибки на сервере

#### Регистрация нового пользователя
**URL**: `/api/v1/register`

**Метод**: POST

**Требуется аутентификация**: Нет

**Тело запроса:**
```json
{
  "login": "имя_пользователя",
  "password": "пароль"
}
```
**Требования**:

- Логин должен содержать минимум 3 символа
- Пароль должен содержать минимум 6 символов
- Логин должен быть уникальным (не существовать в системе)

**Успешный ответ**:

**Статус**: 200 OK

**Содержимое**:
```json
{
  "status": "success",
  "message": "Регистрация успешно завершена"
}
```
- Устанавливает JWT-токен в cookie для автоматической аутентификации
- Создаётся список задач по умолчанию
- Пароль хранится в виде хеша SHA-256

**Ответы с ошибкой**:
- Стутс: `400 Bad Request`
Невыполнение требований к данным
- Статус: `429 Too Many Requests`
При возникновении подозрения на попытку DDoS
- Статус: `500 Internal Server Error`
При возникновении ошибки на сервере

## Модели данных
### Задача (Task)
```json
{
  "name": "string",             // Название задачи
  "description": "string",      // Описание задачи
  "done": boolean,              // Статус выполнения (true/false)
  "date": "string or null",     // Срок выполнения (в формате ISO или null)
  "lvl": number                 // Уровень приоритета
}
```
### Список задач (TaskList)
```json
{
  "data": [
    {
      "name": "string",             // Название задачи
      "description": "string",      // Описание задачи
      "done": boolean,              // Статус выполнения (true/false)
      "date": "string or null",     // Срок выполнения (в формате ISO или null)
      "lvl": number                 // Уровень приоритета
    }
  ],
  "icon": "string"                 // Иконка списка задач (например: "head", "home", "heart")
}
```
### Настройки пользователя (Settings)
```json
{
  "theme": "string",                // Тема ('light' или 'dark')
  "color-date-alert": boolean,      // Включить/выключить стили оповещений
  "sort-order": "string"            // Порядок сортировки ('alphabet', 'date', 'priority', 'count')
}
```

## Обработка ошибок

```json
{
  "status": "error",
  "message": "Описание ошибки"
}
```
